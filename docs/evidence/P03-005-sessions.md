## Delivered behavior

| Area | Implementation |
| --- | --- |
| Credentials | Independent 32-byte random session/CSRF values; unpadded base64url; no claims/PII; kind/domain-separated HMAC-SHA-256 at rest with session-bound CSRF verifier |
| Issuance | Recheck existing active route-selected role; fresh credential every login; optional predecessor revocation only for same principal/kind; return only after transaction commit |
| Authentication | Only correct route-kind token; expiry/revocation/current role/status/security revision checked in MongoDB; explicit internal principal projection without token/digests |
| Rotation | Atomic old revocation plus replacement; one concurrent winner; replay denied; actual new-insert failure rolls back old revocation |
| Revocation | Idempotent supplied-credential logout; per-principal revision plus applicable session revocation atomically; no cross-namespace or other-principal effect |
| CSRF material | Verifier bound to kind/session digest and compared with fixed-length timing-safe bytes; old material invalid after rotation/revocation/expiry/key change; complete Origin/CSRF middleware remains P03-006 |
| Cookie adapter | Exact customer/admin names, host-only, HttpOnly, path /, explicit lax/strict; configured HTTPS always Secure; only configured local/test loopback HTTP exception; matching clear attributes |
| Parsing/guard | Missing/malformed/duplicate selected cookie denied; other cookies cannot substitute; query/Bearer/client role ignored; async route-pinned session-required middleware |
| Configuration | Explicit positive bounded customer/admin TTL and SameSite policy; no invented lifetime/default; field-only failures; SESSION_SECRET rotation fails closed without a dual-key window |

The internal persistence lookup explicitly selects the CSRF verifier for this service. Ordinary model queries still exclude
credential material; callers never serialize raw session documents. SessionOptions are validated at composition, separate
from the existing health-only runtime's environment activation. Sanitized template values remain blank for owner-approved
lifetime/SameSite settings. No package, script, schema/index or CI inventory change was required.

## Operational and integration boundaries

- Public login/provisioning must verify credentials and route kind before calling issue. Public logout still needs
  P03-006 Origin/CSRF protection and fresh-context response composition; safe idempotent revocation is not a CSRF exemption.
- Service transaction callbacks are DB-only; nested independent transactions remain prohibited. Password/security services
  must integrate their revision changes with their own domain transaction rather than treating a cookie as authorization.
- Cookie set follows committed issuance; server revocation must be awaited before reporting logout. Clear only the route's
  cookie; another browser/session/principal cannot be revoked from an arbitrary supplied ID.
- Session reads do not extend expiry. Active role/status/revision and configured key remain authoritative; no stateless JWT,
  client role claim or old-key fallback is introduced.
- Rotate SESSION_SECRET through protected config and drain/restart every old-key process before declaring global rejection;
  no production rotation or mixed-deployment exercise was performed. Actual lifetime/SameSite values require owner approval.
- Guest-order access remains P06-015; CORS/Origin/context/complete CSRF P03-006; verified login/logout route composition
  P03-007/012; rate limits/audit/integrated M1 remain P03-014/016.

API/Database/Operations/Testing/README and sanitized configuration now describe the delivered boundary. The project owner accepted this task on 18 October 2026 under Tasks §2 and AGENTS §13.
This acceptance does not approve milestone or operator gates.
